# Отчёт Этапа 2

## Реализовано

- Сохранена дизайн-система и главная композиция первого этапа.
- Карта восьми учебных групп с реальными состояниями и проверкой всей цепочки предыдущих уроков. Условие перехода к цифрам: завершены все восемь групп; сами данные цифр/цветов/слов относятся к этапу 3.
- Выбор режима перед началом: визуальное сопоставление или звук. Аудиоигра не показывает правильную букву до ответа и разрешает выбор после окончания записи.
- Универсальный AudioPlayer: loading/playing/ended/error, повтор, отмена, запрет автозапуска, тайм-аут, поздний сетевой сбой и защита от гонки старой/новой записи.
- Голосовая запись допускается только с `audioStatus: ready`, `recording.reviewed: true` и непустым `recording.permission`. Ни TTS, ни чужое нелицензированное аудио не добавлялись.
- Чистая логика раунда вынесена в `src/round.js`. Каждая учебная группа проходится полностью, без пропуска букв; младшим предлагаются три варианта, старшим четыре. Свободная практика содержит 5/8 вопросов.
- Пауза и сохранение вопроса в sessionStorage. Постоянный прогресс сохраняется сразу в localStorage. Версия схемы 1 мигрирует в 2.
- Защита от повторной награды и повторного списания жизни. Рано остановленный раунд приносит XP за правильные ответы, но не отмечает урок пройденным и не продлевает серию.
- Живой таймер восстановления, проверки после возврата во вкладку, экспорт/импорт обеих поддерживаемых версий. Старое приложение не перезаписывает неизвестную будущую схему.
- Workbox precaching app shell, NetworkFirst для навигации, CacheFirst для медиа, подготовка согласованных записей целиком и поддержка Range Requests, SWR для будущих отдельных JSON.
- Проверка реального кэша и явное применение обновления. Ошибка сети, удалённый ресурс или нехватка квоты не выдаются за успешную офлайн-подготовку.
- Ремонтный worker для миграции старого адреса сборки этапа 1; нет автоматического reload всех вкладок.
- Подготовлены воспроизводимый генератор PNG/WebP, локальный проверяющий скрипт и GitHub Actions.

## Исправленные Случаи

1. Ранее в младшем режиме урок проверял только первые пять букв группы из шести-семи. Теперь проверяется вся группа.
2. Ранее результат с достаточным процентом мог открыть следующий урок даже при остановке до последнего вопроса. Теперь требуется полный раунд.
3. Повторная обработка одного результата или ошибки могла дублировать XP/штраф. Добавлены идентификаторы обработанных раундов и попыток.
4. Состояние текущего вопроса терялось при перезагрузке. Теперь восстанавливается порядок вариантов, ответ и фаза обратной связи.
5. Кэш HTML обновлялся только после ручной правки VERSION. Теперь навигация проверяет сеть, а worker использует хеш сборки; дополнительная проверка сравнивает SHA-256 HTML.
6. Наличие любого активного worker принималось за готовность офлайн. Теперь проверяются фактические ресурсы кэша.
7. Контроль только соседнего урока позволял неконсистентному сохранению обходить более ранние шаги. Теперь проверяется вся цепочка.

## Что Проверяют Тесты

`tests/progress.test.js`: XP, звёзды, таймер жизни, серия, валидация, запрет хранилища, резервная копия. `tests/round.test.js`: вся цепочка доступа, полный охват группы, переходы фаз, досрочная остановка, повторные события, sessionStorage и миграции.

`tests/audio.test.js`: все состояния AudioPlayer с подставным HTMLAudioElement. Эти тесты не проверяют чеченское произношение и не содержат голосовых файлов. `tests/cache.test.js`: MIME, частичные ответы, нормализация путей, ревизии и SHA-256. `tests/schema.test.js`: полная JSON Schema draft 2020-12 через Ajv. `tests/content.test.js`: алфавит, ссылки уроков и ограничения загрузчика worker.

Playwright проверяет компоновку без горизонтального переполнения, полный урок на 28 XP, сохранение после перезагрузки, отсутствие повторного штрафа, аудиоподсказку, паузу/Escape и офлайн-перезагрузку. Это эмуляция размеров в Chromium, не проверка реальных iPhone/Android.

## Как Закрыть Приёмку

1. Выполнить `npm ci`.
2. Выполнить `node scripts/check.mjs --init-git`. Команда запускает unit, типы, npm audit и опциональную инициализацию Git; сохраняет настоящий отчёт в `docs/check-results.json`.
3. Выполнить `npx playwright install chromium`, затем `node scripts/assets.mjs`. Проверить созданные PNG 192/512/maskable/180 и WebP. Этот скрипт не генерирует речь.
4. Выполнить штатную `npm run build`, затем `npx playwright test`. Изучить `playwright-report`, а не только код выхода.
5. Запустить Lighthouse в Chrome на production preview/HTTPS. Проверить четыре текущие категории, затем отдельно manifest/install/offline/update. В Lighthouse 12+ категории PWA нет.
6. Проверить реальные 360/390/768 px, 200% масштаб, Tab/Shift+Tab/Escape, screen reader и контраст WCAG AA.
7. На HTTPS проверить заголовки и оба сценария обновления: изменение только интерфейса и изменение Workbox. Проверить активный урок во второй вкладке.
8. Подключить согласованные записи хотя бы первой группы, проверить полный звуковой раунд, повтор, отсутствие файла и офлайн-аудио в Safari. Сейчас ни одной голосовой записи нет.
9. Сохранить реальные результаты и только после этого отметить приёмку пройденной.
