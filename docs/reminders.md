# Напоминания И Звук

## Что Реализовано

Это локальные напоминания открытой страницы. Настройки находятся в `profile.preferences.reminders`. По умолчанию `enabled` и `consent` равны false. Доступны подсказка внутри игры и системное уведомление через активный Service Worker.

**Фоновая push-доставка при закрытом приложении не реализована.** Наличие Service Worker и разрешения Notification API не превращает страницу в надёжный будильник. Браузер может остановить страницу или worker. Уже созданное уведомление может оставаться в системе после закрытия, но новые по расписанию в это время не создаются.

## Правила

- Взрослый явно подтверждает согласие, выбирает дни, время и канал, затем нажимает сохранение. Эта галочка не является аутентификацией или настоящим родительским контролем.
- Проверка идёт раз в 15 секунд только при включённой функции; код проверяет видимость страницы и отсутствие урока, модального окна, меню и родительского экрана.
- Разрешено время от 08:00 до 20:30. Подсказка появляется в течение двух часов после выбранного времени, но не с 21:00 до 08:00.
- За пропущенное время очередь не накапливается. Если приложение открыто слишком поздно, сегодняшнее напоминание пропускается.
- После любого записанного раунда за сегодня повторно звать заниматься не нужно, даже если раунд оказался неуспешным.
- Не больше одного напоминания в календарный день; дополнительно действует интервал 18 часов для защиты от повторов при смене часового пояса.
- Дневная отметка сохраняется до отправки. Если не удалось сохранить ограничитель, автоматическая подсказка не отправляется.
- Web Locks согласует показ между вкладками. При отсутствии API остаётся синхронная проверка localStorage и требование фокуса вкладки; это не математическая гарантия отсутствия гонок в старых браузерах.
- С этапа 5 резервирование использует тот же lock, что и игровые сохранения. Перед доставкой согласие, поколение профиля, канал и reservation повторно читаются из localStorage. Старая React-копия не является достаточным разрешением.
- Если системное уведомление не удалось показать, используется внутриигровая подсказка. Напоминание не включается обратно после выключения.
- «Не сегодня» закрывает уже зарезервированную подсказку. Перезагрузка не должна повторно показывать её.

## Системное Разрешение

`Notification.requestPermission()` вызывается только из явного нажатия подтвердившего согласие взрослого, без предварительного асинхронного ожидания. При `denied` повторного запроса нет. При `default`, неподдерживаемом браузере, HTTP или iframe показывается объяснение.

На iOS/iPadOS поддерживаемая версия Safari требует веб-приложения, добавленного на главный экран. Это не проверено на реальном iPhone в текущей среде. При ожидающем обновлении worker сначала предлагается обновить приложение.

`showNotification` использует `silent: true`, `renotify: false`, `requireInteraction: false` и фиксированный tag. Нет специально заданных вибраций или настойчивого удержания уведомления. Фактический показ зависит от ОС, режима «Не беспокоить» и настроек устройства: успешный Promise означает принятие браузером, не гарантированный показ.

Проверочная кнопка отправляет тест только по явному действию и ограничивает повтор на 15 секунд. Она не включает расписание сама. В payload нет имени, XP, списка слов или истории ребёнка. При клике открывается только собственный `/#learn`; произвольный URL из данных не используется. Если игра открыта, вкладка фокусируется без navigate/reload, а активный урок не прерывается.

Выключение функции закрывает уведомления с тегами игры. Разрешение браузера остаётся у пользователя. Импорт прогресса сбрасывает согласие и выбирает канал «внутри игры» в выключенном состоянии.

Добавлен epoch отмены для незавершённых showNotification и проверка живого согласия в настройках. Если операция завершилась после тайм-аута/отключения, приложение пытается закрыть запоздалое уведомление. Сам вызов браузерного API отменить нельзя; абсолютную невозможность краткого показа ОС при такой гонке код не обещает. При отказе хранения или неизвестном формате автоматическая доставка не выполняется.

## Если Нужен Настоящий Push

Понадобится отдельно согласовать сервис отправки: он хранит push-подписку браузера и отправляет Web Push в подходящее время. Подписка содержит endpoint и ключи; это сетевые идентификаторы и дополнительная поверхность безопасности. Нужны отписка, ограничения частоты, часовые пояса, минимизация данных и политика для семей с детьми.

Без отдельного решения пользователя сервер, Firebase/Supabase, push-подписки, VAPID-ключи и сторонние SDK не добавлялись. Не следует маскировать `setInterval`, Background Sync или экспериментальные API под гарантированное расписание при закрытой игре.

## Неголосовые Эффекты

`data/effects.json` описывает успех, поддержку после ошибки и завершение. `src/effects.js` создаёт синусоидальные тоны через Web Audio. Они короче секунды, с плавным нарастанием/затуханием и ограниченной громкостью. Это не речь, не TTS и не попытка произнести чеченские звуки.

Вместо отдельных MP3/WAV используются несколько частот и времён в JSON: файлы не скачиваются, офлайн-звук не зависит от сети. На первом экране AudioContext не создаётся. Он создаётся или возобновляется при действии пользователя; ошибки и тайм-аут не прерывают игру. Можно выключить эффекты в уроке, профиле или семейных настройках. При скрытии страницы, паузе, начале записи носителя и отключении звука активные тоны останавливаются.

Носителей голоса по-прежнему нет. Кнопка произношения не заменяется музыкальным эффектом. Правила записи и разрешений: `docs/audio.md`.
