# Security-аудит Этапа 5

## Область И Вердикт

Проверена клиентская обучающая PWA «Нохчийн Мотт»: React + Vite, localStorage, sessionStorage, Workbox, импорт/экспорт JSON и добровольные локальные уведомления. Сервер приложения, аккаунты, платежи, сторонняя аналитика и Push-подписки отсутствуют. Это аудит исходного кода и доступной сборки, **не независимый пентест и не сертификат безопасности**.

Названия OWASP сверены с официальным выпуском: https://top10.owasp.org/2025/ . Каждый пункт ниже рассматривается применительно к реальной архитектуре, а не помечается выполненным только из-за отсутствия сервера.

**Вердикт: публичную приёмку пока не закрывать.** Исправлены обнаруженные дефекты, подготовлена автоматическая защита production-артефактов. Но строгая CSP/SRI-подготовка, unit-тесты, браузерные сценарии и проверка реального хостинга в этой среде не запускались. npm продолжает сообщать об одной low-уязвимости. Эти ограничения не скрываются за успешной сборкой.

## Границы Доверия

- JSON из файла, localStorage и sessionStorage недоверенный: он проверяется до использования. Нельзя считать профиль с устройства авторизованным или защищённым от редактирования.
- JSON уроков входит в доверенную сборку репозитория. Изменение репозитория или зависимости означает изменение поставляемого кода; runtime-валидация не заменяет review поставки.
- Имя является необязательным локальным прозвищем. Родительская галочка означает согласие, а не проверку возраста, личности или права доступа.
- Напоминание не является фоновым Push. Системное разрешение контролируется браузером; данные для уведомления нейтральны и не включают профиль.
- Манифест выпуска и хеши доставляются тем же HTTPS-origin. Они обнаруживают несовпадение артефактов и повреждение кэша, но **не защищают от полного захвата origin или build-среды**.
- Администратор хостинга, TLS, DNS, инфраструктурные access-логи и права GitHub не находятся под управлением этого клиентского кода.

## Проверка Поставки

Точные версии всех прямых зависимостей записаны `install_npm_packages` с `.npmrc: save-exact=true`, package.json вручную не редактировался. Повторная установка выдала: `audited 136 packages`, `1 low severity vulnerability`.

По этому краткому выводу нельзя достоверно назвать пакет, CVE или применимость оставшейся уязвимости. Проверялись версии нескольких транзитивных пакетов и публичные advisory, но это **не замена npm audit --json**. Поэтому остаток явно открыт, а не отнесён к безопасному dev-only риску без доказательств.

Actions закреплены по значениям официального GitHub API для refs/tags/v4:

- checkout: `11d5960a326750d5838078e36cf38b85af677262`.
- setup-node: `49933ea5288caeca8642d1e84afbd3f7d6820020`.
- upload-artifact: `ea165f8d65b6e75b540449e92b4886f43607fa02`.

Само закрепление SHA не означает аудит исходников этих actions. Доступ к secrets и инфраструктуре CI должен быть минимальным; workflow использует contents:read, не pull_request_target.

## Production CSP И Выпуск

1. Сначала обычная сборка `npm run build`.
2. Затем `node scripts/harden.mjs` обрабатывает уже готовый dist. Он не запускает собственную сборку, не меняет vite.config.ts или package.json.
3. Скрипт вычисляет SHA-256 конечных script/style блоков, вставляет CSP meta до кода и генерирует HTTP-политики. Нельзя менять HTML после этого шага, включая автоматическую минификацию CDN.
4. Создаются release.js и release-manifest.json с точными размерами/типами/SRI всех опубликованных файлов. Worker проверяет эти значения. Перечень не является цифровой подписью владельца.
5. Создаются dist/_headers и dist/.htaccess. Флаг `--vercel` формирует только статические файлы и Build Output API v3 в .vercel/output; функций сервера нет.
6. `scripts/serve.mjs` позволяет Playwright проверять уже защищённый dist с настоящими HTTP-заголовками, а не обычный preview, игнорирующий _headers.

`vercel.json` и `netlify.toml` вызывают подготовку после штатной сборки. Для ручного Hostinger-деплоя нужно выполнить подготовку и проверить, что Apache применяет .htaccess. Ни Vercel, ни Netlify, ни Hostinger в этой среде не развёртывались.

**Raw build остаётся режимом предпросмотра.** В нём `public/release.js` содержит null, а шаблон _headers не имеет вычисленных script/style хешей. Строгая защита выпуска появляется только после успешного harden. Документ не утверждает обратного.

HSTS не использует includeSubDomains/preload без решения владельца домена. CSP не содержит `upgrade-insecure-requests`, чтобы не сломать localhost; HTTPS и HTTP-redirect обеспечивает выбранный хостинг. `frame-ancestors 'none'` действует через HTTP, а не meta. Cookie/analytics endpoints не добавлены.

## Неподтверждённое

- `scripts/harden.mjs`, `scripts/check.mjs`, unit, Playwright, Lighthouse и npm audit --json не запускались из-за отсутствия терминального/браузерного инструмента.
- Git init и генератор PNG/WebP также не выполнялись. Встроенное SVG и исходный большой PNG остаются.
- Только начальный JS gzip не измерен отдельно; успешный HTML build не доказывает лимит JS или мобильный Performance.
- Нужны реализация проверки на реальном HTTPS-домене, корректные MIME и Cache-Control, ручной update/offline/Safari прогон, WCAG и проверка носителем языка.
- Требуется исправить или документированно разобрать оставшуюся npm low. CI-аудит выставлен на low и сейчас должен блокировать принятие, пока предупреждение не устранено.

## Критерии Приёмки

Выполнить npm ci и scripts/check.mjs; получить полный audit, устранить проблему без непроверенного audit fix --force. Подготовить PNG/WebP и обычный dist, выполнить harden, затем все Playwright-сценарии. Проверить, что сторонний inline-script блокируется, приложение и прогресс работают без CSP violation, импорт не применяется до подтверждения, чужой/будущий snapshot не заменяется, отменённое напоминание не доставляется, случайные медиа не кэшируются и повреждённый ресурс не принимается.

Только после успешных фактических запусков и проверки хостинга заменить статусы на подтверждённые. Не выдавать этот документ за заключение независимого аудитора.

## Дополнение Этапа 6

Сквозная ревизия не закрыла неподтверждённые проверки автоматически: `docs/project-review.md`. Добавлены отдельные CSP и X-Robots-Tag для **всех** HTML-документов, support XML/MIME, настоящая 404 и проверка финальных артефактов. Изменён порядок публикации: штатная сборка -> scripts/publish.mjs, внутри prerender -> harden -> verify-release.

Публичные страницы не читают профиль; аналитика явно выключена. Повторная инициализация не теряет более свежее состояние памяти после ошибки квоты. Repair кэша проверяет хеш существующего файла и заменяет повреждённый, а не просто проверяет наличие ключа. Эти исправления имеют новые регрессионные сценарии, но их исполнение здесь по-прежнему не подтверждено.

Установочный аудит снова сообщил 1 low. Полный npm audit, тесты, генераторы, real HTTPS/CSP и Lighthouse остаются обязательными до приёмки. Не трактуйте это дополнение как закрытие security-остатков или одобрение релиза.
