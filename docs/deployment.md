# Подготовка И Публикация

## Решения Владельца

Публичный домен ещё не указан. В `data/site.json` origin=null, indexing=false. Внешняя аналитика выключена и провайдера нет. Не меняйте это на случайный пример домена: canonical, Open Graph и sitemap должны ссылаться на ваш настоящий согласованный HTTPS-origin.

После security-приёмки задайте `SITE_URL` в переменных среды хостинга: полный HTTPS-origin без пути, query, credentials или порта. Для индексации отдельно задайте `SITE_INDEXING=1`. Либо укажите эти значения в data/site.json после согласования. Примерный домен в продукт не добавлен.

`SITE_INDEXING=0` явно выключает индексацию даже при настройке true в репозитории. Vercel preview и Netlify deploy-preview/branch-deploy принудительно остаются noindex. Опечатка в переменной, например `true` вместо `1`, останавливает подготовку, а не включает индексацию неявно.

Пока индексация не разрешена, meta robots и X-Robots-Tag содержат noindex/nofollow/noarchive. Robots.txt разрешает чтение HTML, чтобы crawler мог увидеть noindex; файл не является средством защиты персональных данных. Sitemap остаётся пустым. После разрешения он содержит только четыре публичных URL, не hash-профили или историю детей.

## Порядок Локальной Приёмки

1. `npm ci`.
2. `node scripts/check.mjs --init-git`. Команда не собирает приложение: запускает подготовленные unit/type/audit проверки, при необходимости Git и проверяет существующий bundle. Разобрать результаты, включая оставшуюся low-уязвимость.
3. `npx playwright install chromium`, затем `node scripts/assets.mjs`. Будут созданы PNG 192/512/maskable/180, WebP-пейзаж и JPEG-превью 1200x630. Проверить картинки.
4. Штатная `npm run build`.
5. `node scripts/publish.mjs`. Скрипт выполняет prerender, harden и verify-release над уже готовым dist, но сам Vite не запускает.
6. `npx playwright test`. Локальный scripts/serve.mjs выдаёт реальные подготовленные CSP и HTTP-коды. Изучить отчёты и скриншоты всех четырёх viewport.
7. Повторить `node scripts/check.mjs`, чтобы получить размер последнего JS-bundle, а не устаревшего dist.
8. Открыть Chrome DevTools Lighthouse на подготовленном локальном/HTTPS-выпуске. Сохранить настоящий отчёт, проверить отдельно offline/install/update, Safari, клавиатуру, screen reader и 200% масштаб.

`scripts/publish.mjs`:

- Создаёт статический HTML главной и три публичные страницы из общих данных.
- Не использует игровой профиль, имена, XP, историю и браузерные API при prerender.
- Формирует title/description, OG/Twitter, WebApplication/Course/FAQPage, robots/sitemap и 404.
- Вычисляет CSP/SRI по **окончательным** файлам и назначает HTTP-CSP каждой HTML-странице.
- Проверяет контрольные суммы, заголовки, FAQ, h1, локальные ссылки и бюджет начального JS.
- При разрешённой индексации требует наличие подготовленных растровых иконок, WebP и share.jpg.

Новая сборка требует повторного publish. Не запускайте prerender после harden и не включайте HTML-minify/CDN-переписывание после формирования контрольных сумм. Скрипт намеренно отклоняет уже защищённый вход, чтобы не легализовать произвольные изменения.

## Что Получится

| URL | Содержимое |
| --- | --- |
| `/` | Игра с публичным статическим первым HTML и FAQ |
| `/about.html` | Цель проекта, формат обучения и FAQ, без application JavaScript |
| `/privacy.html` | Описание данных и управления ими, без чтения сохранений |
| `/sources.html` | Источники и правила произношения/прав на записи |
| `/404.html` | Страница ошибки, noindex, не выдаётся за игровую главную |
| `/robots.txt` | Правила crawler и ссылка на sitemap только для разрешённого домена |
| `/sitemap.xml` | Только существующие публичные страницы либо пустой preview sitemap |

В dev-режиме Vite публичные URL показывает компонент App. В подготовленном dist эти страницы являются самостоятельными HTML и не требуют JavaScript. Только первая загрузка статической публичной страницы без предварительного посещения игры не устанавливает SW; offline-кэш готовится при открытии самой игры.

## Хостинги

Vercel: vercel.json вызывает штатную сборку и `node scripts/publish.mjs --vercel`. Используется статический Build Output API v3, backend-функций нет. Для автоматического выпуска растровые ресурсы должны быть заранее подготовлены и включены в репозиторий либо их генерация должна быть настроена в подходящей build-среде с Chromium.

Netlify: netlify.toml вызывает сборку и publish. Заголовки берутся из сгенерированного dist/_headers. Незнакомый путь получает 404, а не автоматическую подмену главной страницей. Проверить, что настройки панели хостинга не добавляют старый wildcard rewrite.

Hostinger/Apache: загрузить **подготовленный** dist с .htaccess; убедиться, что mod_headers, DirectoryIndex, ErrorDocument и типы файлов действительно применены. Не копировать только index.html без release.js и остальных ресурсов.

На всех хостингах проверить HTTPS и редирект HTTP, домен www/non-www, MIME WOFF2/SVG/XML/manifest, Cache-Control release.js/sw.js, CSP каждой страницы и независимую 404. HSTS не включает includeSubDomains/preload автоматически. Фактический деплой в этой среде не выполнялся.

## После Деплоя

Проверить четыре canonical URL, картинки шаринга по абсолютным адресам и отсутствие случайного noindex только если приёмка уже разрешила индексирование. Добавить домен в Search Console от имени владельца и отправить sitemap вручную. Наличие sitemap или JSON-LD не гарантирует индексацию, сниппет или рекомендации AI-поиска.

В Google FAQ rich results больше не показываются с мая 2026 по документации Search Central. FAQPage оставлен как валидное описание видимых ответов, без обещания расширенного результата. Специальный llms.txt не нужен для Google и в этом проекте не генерируется ради фиктивного «GEO-балла».
