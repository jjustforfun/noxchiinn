# Нохчийн Мотт

Игровое знакомство с чеченским языком для детей от 5 лет. Родной язык, близкие корни, маленькие ежедневные открытия.

## Статус

На этапе 7 в среде с настоящим терминалом впервые прогнаны подготовленные проверки: **337 unit-тестов проходят**, `tsc --noEmit` чист, `npm audit` показывает **0 уязвимостей** (оставшийся low-esbuild закрыт закреплённым override), сгенерированы растровые PNG/WebP/JPEG, выполнена цепочка `build → publish` (**127/127 проверок артефактов пройдено**), начальный JS = 133 КБ gzip (бюджет < 200 КБ). Существующий дизайн, 8 тем, 117 карточек, 24 урока, игры, календарь, семейные настройки и эффекты сохранены.

**Это ещё не финальный публичный релиз.** Остаются реальные блокеры (полный список — в [docs/stage-7.md](docs/stage-7.md)): 42 браузерных Playwright-сценария и Lighthouse не запущены, потому что **Chromium в этой песочнице недоступен для скачивания** (сеть блокирует загрузку); нет записей носителей языка; не проведена лингвистическая рецензия преподавателя; не согласованы домен и хостинг; не выполнены проверки на реальных устройствах, со скринридером и при 200% масштабе.

Механика «слушаем и выбираем» реализована, но **аудио носителей пока отсутствует** (0 из 118 записей). Звуковой режим не выдаёт заглушки за речь: он станет доступен после подключения полного согласованного комплекта записей. При ошибке звука есть повтор и переход к визуальной игре без потери жизни. Все слова и русские пояснения имеют статус `native-review-needed`: сверка с источниками не заменяет проверку преподавателем. Полный список отсутствующих записей — в [docs/audio-checklist.md](docs/audio-checklist.md).

## Публичные Страницы

- `/about.html`: цель проекта, формат обучения и восемь FAQ для семей.
- `/privacy.html`: какие данные остаются на устройстве и как управлять сохранениями.
- `/sources.html`: реальные источники, спорные формы и правила аудиопроизношения.
- `/`: прежняя игра с видимым FAQ ниже игрового контента и нейтральным статическим первым HTML.

Публичные страницы не читают профиль. После подготовки выпуска они не требуют JavaScript, а вопросы работают через нативные details. Текст и JSON-LD берутся из одних JSON-файлов. Полных ce/en-страниц нет, поэтому hreflang не изображает несуществующие переводы.

В `data/site.json` домен пока не задан, индексация выключена, аналитика отсутствует. Для включения SEO-индексации после приёмки нужны согласованный `SITE_URL` и явный `SITE_INDEXING=1`. Без них нет выдуманных canonical/OG URL; sitemap пустой, preview имеет noindex. См. docs/deployment.md. Это не способ скрыть личные данные: их просто нет в публичном HTML.

## Семейные Возможности

1. Нажмите на огонёк серии в шапке или «Календарь занятий» в профиле. Можно переключать месяцы и выбирать день. Зелёным отмечен успешный день, бежевым попытка; старые занятия не дорисовываются.
2. Откройте «Родителям»: сводка за 7/30 дней, календарь, последние раунды и прогресс каждой темы. Это статистика игры, не оценка уровня владения языком.
3. В «Семейных настройках» выберите цель 12/20/32 XP, выключите звуковые эффекты или настройте напоминание. Цель сохраняется сразу; напоминание включается отдельной кнопкой после согласия взрослого.
4. Напоминания по умолчанию выключены. Они работают только в видимой открытой игре, вне урока, в выбранный день и дневное время. При закрытой странице **ничего не доставляется**. Подробности: [docs/reminders.md](docs/reminders.md).

Системная проверка использует Notification API и активный Service Worker, а не Push API. Настоящая фоновая push-доставка потребовала бы отдельного сервиса отправки и согласования данных; она намеренно не подключена. На iOS системные веб-уведомления требуют установленного веб-приложения и поддерживаемой версии Safari. Согласие взрослого является добровольным подтверждением, не паролем и не проверкой личности.

Короткие звуки успеха, поддержки и завершения создаются локально через Web Audio после пользовательского действия. Это синусоидальные музыкальные тоны по `data/effects.json`, **не TTS и не чеченское произношение**. Дополнительные MP3/WAV для них не загружаются. Есть громкость и выключение в профиле, у родителей и непосредственно в уроке.

## Попробовать Игры

1. Откройте «Тренировка» в меню или нажмите «В мастерскую» на главном экране.
2. Выберите тему: цифры, цвета, первые слова, семья, еда, животные, тело или алфавит.
3. Нажмите «Найди пару», «Собери слово» или «Быстрые открытия», затем «Поехали!».
4. В тренировке доступны все готовые темы без потери жизней. Основная карта открывается последовательно; практика не обходит её.

В алфавите остаются узнавание букв и викторина, а пары и сборка предназначены для слов, чисел и цветов. Природа обозначена как будущая тема, её контент не имитируется.

## Почему Такой Стек

Среда проекта уже настроена на React, Vite, Tailwind CSS и `src/App.tsx`. Поэтому сохранена её рабочая конфигурация, вместо параллельного Astro-проекта. Это явное отклонение от пожелания vanilla JS/Astro.

Игровая логика, звук, сохранение и PWA написаны на простом JavaScript с русскими JSDoc-комментариями. Типы используются только в небольшом слое интерфейса. Чтобы менять учебный контент, знать React или TypeScript не нужно: достаточно редактировать JSON.

Сервера приложения, аккаунтов, cookies-прогресса, CDN-скриптов, рекламы и аналитики нет. Nunito с расширенной кириллицей публикуется локальными WOFF2 с preload и font-display:swap, а не внешним Google Fonts запросом. Workbox собирается локально. Отдельные Node-скрипты подготовки и локального тестового сервера не являются backend продукта.

## Запуск

1. Установите Node.js 22.12 или новее и редактор VS Code.
2. Откройте папку проекта и терминал внутри неё.
3. Выполните `npm ci`, чтобы установить версии из `package-lock.json`.
4. Выполните `npm run dev` и откройте адрес, который покажет Vite.

Для готовой сборки используется `npm run build`. Команда `npm run preview` позволяет открыть её локально. Service Worker намеренно отключён на dev-сервере, чтобы старые кэши не мешали разработке.

Для тестов выполните `npx vitest run --config vitest.config.js`. Для проверки зависимостей выполните `npm audit`. Для проверки типов: `npx tsc --noEmit`.

Объединённая локальная проверка: `node scripts/check.mjs`. Она запускает Vitest, проверку типов и npm audit, затем записывает настоящий отчёт в `docs/check-results.json`. Флаг `--init-git` дополнительно инициализирует Git, только если его ещё нет. Скрипт не запускает сборку.

Для браузерных сценариев выполните `npx playwright install chromium` и `node scripts/assets.mjs`, подготовьте `dist` штатной `npm run build`, затем выполните **`node scripts/publish.mjs`** и `npx playwright test`. Publish последовательно выполняет публичный prerender, harden и проверку финальных артефактов. Конфигурация запускает локальный scripts/serve.mjs с настоящими CSP и HTTP-кодами. При любой новой сборке publish нужно повторить; менять файлы после SRI или дважды обрабатывать тот же HTML нельзя.

GitHub Actions содержит независимые задания тестов и npm-аудита. Аудит настроен на low, поэтому оставшееся предупреждение должно блокировать приёмку, но не мешает получить результаты остальных тестов. Actions закреплены commit SHA, прямые npm-версии закреплены точно. Наличие workflow и Dependabot не означает выполненную проверку или успешное развёртывание.

## Как Добавить Букву Или Урок

1. Откройте `data/alphabet.json`.
2. Найдите похожую запись в `items` и скопируйте её целиком.
3. Измените `id`, `chechen`, `lower`, `russian` и `transcription`.
4. В `audio` укажите будущий путь `/audio/имя.mp3`. Пока записи нет, оставьте `audioStatus: "pending"`.
5. Добавьте новый `id` в массив `items` нужного урока из `lessons`.
6. Проверьте JSON: после соседних записей нужна запятая, после последней её быть не должно.
7. Запустите тесты и посмотрите изменения в браузере.

Для новой темы создайте JSON по `data/lesson.schema.json`, импортируйте его в массив `courses` файла `src/catalog.js` и добавьте тему с настоящим числом уроков в `data/topics.json`. Карта, словарь, доступные режимы и прогресс теперь используют общий каталог. Для совершенно нового типа заданий потребуется отдельная механика, но для обычных слов менять интерфейс не нужно.

У каждой новой карточки есть уникальный ID, чеченское написание, русское значение, пояснение, путь к аудио и возрастная группа. Для картинки укажите `/images/vocabulary.svg#имя-символа`; соответствующий SVG-символ должен существовать. Для числа используйте `number`, для цвета `swatch` в формате `#rrggbb`. Цвет всегда сопровождается текстовой подписью. Источник задаётся `sourceId` у карточки или `sourceIds` у темы и ссылается на реестр `data/sources.json`.

Названия полей: `title` = тема, `level` = уровень, `items` = буквы/слова, `chechen` = чеченское написание, `russian` = русское пояснение, `transcription` = ориентир по-русски, `audio` = путь к записи, `image` = путь к картинке или `null`, `ageGroup` = `all`, `5-8` либо `9+`.

**Важно:** русское пояснение не заменяет произношение чеченского звука. Материал помечен `native-review-needed`, пока его не проверит носитель-преподаватель. Используйте знак палочки `Ӏ` (U+04C0), а не цифру `1` или латинскую `I`.

## Сохранения

Ключ localStorage: `nohchiin-mott:progress`, версия схемы: `4`. Версии `1`, `2` и `3` мигрируют с сохранением XP, оценок, изученного материала, серии и обработанных событий. Добавлены лучшая серия, семейные настройки, дневные сводки и последние раунды. Подробная история начинается только после обновления: из старых XP нельзя восстановить даты и результаты отдельных занятий. Старое приложение не должно перезаписывать новую схему.

`activity` хранит суммы не более чем за 366 дат: количество раундов, успешных раундов, тренировок, XP, правильных ответов и общее число заданий в полностью завершённых раундах. Досрочно остановленные раунды не входят в процент точности, но их XP и факт попытки остаются. `history` содержит последние 80 раундов: дату без времени, ID урока, режим и итог; ответы по каждому слову в постоянный журнал не копируются.

Текущая серия требует успешного полного раунда за соседние календарные дни. При пропуске лучшая серия и знания остаются. Календарные операции не прибавляют 24 часа к местной полуночи, поэтому переход на летнее время не разрывает соседние даты. При переезде назад через полночь допускается предыдущая запись на один календарный день впереди; старые даты не переписываются. Не стоит вручную менять часы ради серии: это локальная учебная игра, не защищённый от подмены времени сервис.

В `sessionStorage` по ключу `nohchiin-mott:round` находится только текущий раунд: порядок вопросов/вариантов, ответы, фаза, выбранные фишки, найденные пары и остаток таймера. Схема раунда 2 читает старую схему 1. Сессия действует до 12 часов в текущей вкладке, не является межустройственным сохранением и не включается в экспорт профиля. После сброса/импорта профиля старый раунд не применяется.

В игре на пары ошибка исправляется, но XP и звёзды отражают первую попытку. При последней потере жизни сопоставление останавливается и не засчитывает незавершённый урок. Викторина доступна только в тренировке: 90 секунд для 5-8 лет и 60 для 9+. Таймер не идёт во время паузы, скрытой вкладки и разбора ответа; его можно не выбирать вообще. В сборке слова готовые пробелы и дефисы не переставляются, а диграфы алфавита остаются одной фишкой. Подсказка разрешена без штрафа.

Хранятся локальное прозвище, возрастной режим, аватар, игровой прогресс и семейные настройки. Дата считается по местному календарю устройства, не по UTC. Разрешение Notification API не сохраняется как доверенный флаг: оно читается у браузера. В уведомление не попадают имя, очки, история и расписание ребёнка. Изменения из соседней вкладки подхватываются; это не серверная синхронизация и не распределённая транзакция между устройствами.

Повреждённое сохранение не должно обрушить приложение. Значения проверяются и ограничиваются. Для неизвестной будущей версии или невалидного JSON делается одна локальная резервная копия `nohchiin-mott:progress:recovery`, если браузер разрешает запись. Более новая схема не перезаписывается старым приложением: оно показывает ошибку сохранения. Миграции следующих версий нужно добавлять явно в `migrate`.

JSON проверяется до использования: максимум 250000 UTF-8-байт, глубина 14, 20000 узлов; запрещены prototype-ключи и accessor-объекты. Слишком большой неизвестный снимок остаётся нетронутым в read-only режиме. Ошибки записи показываются постоянно, а не только временным toast. Игровые записи и резервирование напоминаний используют один Web Lock; без поддержки API остаётся сравнение текущего снимка, не абсолютная гарантия транзакций между вкладками.

Импорт сначала проверяет файл и показывает сравнение. **Только кнопка подтверждения заменяет профиль**; до этого можно отменить или скачать текущее сохранение. Неудачная запись замены не удаляет старый профиль. Экспорт содержит только разрешённые поля, не сырую резервную копию и не ответы сессии. Файл не отправляется на сервер. Напоминания из файла выключаются и требуют нового согласия. Системное permission можно отозвать только в настройках браузера.

## Офлайн И Установка

В опубликованной сборке Workbox предварительно сохраняет приложение, изображения, SVG-иллюстрации, иконки и запасную страницу. Все восемь тем импортируются из JSON и уже находятся в app shell. Иллюстрации получают хеш Vite в имени, поэтому их изменение обновляет адрес ресурса и worker. Для будущих отдельно загружаемых `/data/` настроен stale-while-revalidate; для аудио, шрифтов и изображений настроен cache-first. HTML-ошибка хостинга не кэшируется вместо MP3 или JSON.

Защищённый выпуск после publish использует предварительно сохранённые файлы с SRI SHA-256, проверку MIME, размера и тела. Публичные HTML, XML и локальные шрифты включены в выпуск. Обновление обнаруживается по release.js и release-manifest.json. Повреждённый ресурс не принимается и при восстановлении скачивается заново. Случайные media URL не кэшируются. Неподготовленный preview использует NetworkFirst без release-SRI и не считается production security-режимом.

Окно установки проверяет реальное наличие ресурсов. Range Requests поддерживает полные сохранённые аудиофайлы. Согласованные записи по-прежнему отсутствуют, TTS не используется.

1. Откройте сборку через HTTPS или localhost и дождитесь установки worker.
2. В окне «Установить приложение» проверьте сообщение о сохранении алфавита для офлайн-игры.
3. Отключите сеть, перезагрузите страницу и пройдите визуальный урок.
4. Проверьте, что XP остаётся после ещё одной перезагрузки.

Номер выпуска вычисляется из финальных файлов в scripts/harden.mjs. Суффикс `v3` в именах runtime-кэшей обозначает структуру кэша, а не ручной номер каждого деплоя. При замене аудио продолжайте менять `recording.revision`. После любой подготовки изображений или prerender сначала пересоберите dist, затем выполните harden; изменять подписанные хешами файлы после этого нельзя.

Кнопка обновления не перезагружает активный урок, требует закрыть другие вкладки игры и ждёт подтверждённой активации. При ошибке importScripts неполный worker не устанавливается; аварийная активация этапа 1 удалена. В защищённом выпуске разрешённый worker выбирается из локального release.js. Эти сценарии требуют настоящего браузерного прогона. SHA-256 не заменяет HTTPS, подпись владельца, безопасность CI или защиту от полного захвата origin.

Существующий Vite-плагин собирает HTML, JS, CSS, данные и шрифты в `dist/index.html`. Workbox находится в отдельном файле `dist/service-<hash>.js`, а корневой `sw.js` загружает только разрешённый локальный путь. На другом build-конфиге нужно повторно проверить фактические пути.

На этапе 7 физические растровые ресурсы **сгенерированы и лежат в репозитории**: `public/icons/icon-192.png`, `icon-512.png`, `maskable-512.png`, `apple-touch-icon.png`, `public/images/learning-landscape.webp` (~22 КБ) и `public/images/share.jpg` (1200×630). Manifest переключён на PNG-иконки, в `index.html` подключён Apple Touch Icon.

Штатный `scripts/assets.mjs` использует Chromium из Playwright; в этой песочнице Chromium скачать нельзя, поэтому те же файлы созданы через `sharp` (librsvg + libwebp) с идентичными именами, размерами, фоном `#eaf2dc` и качеством WebP 82 / JPEG 87. Если у вас есть Chromium, канонический путь — `node scripts/assets.mjs`; результат совпадает. Проверка разрешённого индексируемого выпуска не пропустит отсутствие подготовленных ресурсов.

## Публикация И Безопасность

`vercel.json` вызывает штатную сборку и `scripts/publish.mjs --vercel`, который создаёт статический Build Output API v3 в `.vercel/output`. `netlify.toml` публикует dist после publish. Для Hostinger создаётся .htaccess с CSP каждой HTML-страницы и настоящей 404; поддержку mod_headers надо проверить. Обычный preview Vite эти заголовки не применяет. Домены, сертификаты и deploy не настроены фиктивно.

В starter-проекте скрипты и стили инлайнятся. Hardening-скрипт вычисляет их точные CSP-хеши, без unsafe-inline, unsafe-eval или статического nonce. Компоненты больше не используют style attributes, поэтому запрещён и style-src-attr. Есть отдельная политика для worker, чтобы CSP документа не ломала importScripts. CSP meta защищает код, а HTTP frame-ancestors запрещает framing. Добавлены nosniff, no-referrer, COOP/CORP, Permissions-Policy и HSTS без includeSubDomains/preload.

На этапе 7 цепочка prerender → CSP/SRI → проверка артефактов **исполнена**: `node scripts/publish.mjs` запечатал 29 локальных ресурсов и прошёл 127/127 проверок артефактов (SRI, CSP каждой страницы, единственный h1, FAQ JSON-LD, локальные ссылки, бюджет JS, noindex-режим preview). Отчёты — в `docs/release-checks.json` и `docs/release-security.json`. Это статическая проверка артефактов, **не браузерная приёмка**: `browserVerified` и `lighthouseVerified` в отчёте остаются `false`, потому что Chromium в песочнице недоступен. Не публикуйте raw dist без повторного publish на своём домене. Не включайте минификацию HTML на CDN после вычисления хешей.

Vite 7.3.5 и остальные прямые версии закреплены точно. На этапе 7 разобран остаток npm audit: единственной low-уязвимостью была `esbuild` (GHSA-g7r4-m6w7-qqqr, CVSS 2.5, чтение файлов dev-сервером только под Windows), приходящая транзитивно через Vite. Она закрыта закреплённым `overrides.esbuild` (0.28.2), после чего `npm audit` сообщает **0 уязвимостей**, а сборка, 337 тестов и `tsc` продолжают проходить. CI выделяет аудит в отдельное задание с порогом low. Подробности: docs/security-audit.md.

Не используйте dev-сервер Vite как production-сервер. На хостинг загружается `dist`. Домен не задан: canonical, абсолютные Open Graph URL, sitemap и настоящие языковые страницы добавляются после его выбора на этапе 6.
